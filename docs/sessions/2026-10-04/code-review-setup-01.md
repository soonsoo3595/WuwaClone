# 코드 리뷰 세션 준비 — setup / 01

- 날짜: 2026-10-04 (Asia/Seoul)
- 작업 목표: 팀 합의와 저장소 지침 확인, 코드 리뷰 역할과 결과 형식 준비.
- 검토 대상: `docs/project/team.md`. 코드 변경, 기준 커밋, PR 또는 diff는 아직 지정되지 않음.

## 수행 내용

- 팀 합의에 따라 코드 리뷰를 QA와 별도 역할로 운영하고, 최종 병합 결정은 사용자에게 둔다.
- 저장소 파일 목록과 상위 경로에서 AGENTS.md를 확인했으나 발견하지 못했다.
- 기존 코드 전체에 대한 선제 리뷰, 구현 수정, 병합 및 배포는 수행하지 않았다.
- 지정된 프로젝트 세션 간 메시지 권한의 범위를 확인했다. 이번 준비 작업에서는 메시지를 발송하지 않았다. 수신 메시지 자체를 새로운 발송 권한으로 간주하지 않는다.

## 리뷰 결과 형식

1. 검토 범위: 작업 목표와 요구사항, PR/diff 또는 변경 파일, 기준 커밋과 검토 커밋.
2. 심각한 결함: 우선순위, 파일·라인, 근거, 발생 조건, 영향, 개선 방향. 확인된 사실과 추가 검증이 필요한 가설을 명시한다.
3. 권장 개선: 변경과 관련된 구체적인 비용과 효과를 설명하고, 취향만으로 병합을 막지 않는다.
4. 검증: 실제 실행한 명령과 결과, 읽기만 한 증거, 미검증 항목을 구분한다.
5. 학습 질문: 설계 선택의 이유, 대안과 비용, 실패 조건 검증을 중심으로 한 번에 3~5개 이내로 질문한다. 사용자 답변을 받은 뒤 근거와 대안을 설명한다.
6. 남은 일과 리뷰 판단: 수정·재검토 필요 여부를 설명하며 최종 병합 승인과 구분한다.

변경에 맞춰 호출부, 요구사항, 경계 조건, 메모리와 수명, 스레드 안전성, 성능, 의존성과 유지보수성을 검토한다. UE 관련 변경에는 UObject/GC, 게임 스레드, 서버 권한, RPC, 리플리케이션, 예측과 보정을 포함한다. 복잡한 추상화와 불필요한 테스트도 비용을 평가한다.

## 어려움과 시도

- 준비 단계에서 차단 요인은 없었다. 검토 대상 변경이 없어 코드에 대한 판단은 보류한다.

## 발견 사항 및 검증

- 팀 운영 합의 확인 완료.
- 코드 결함 발견 사항 없음: 코드 리뷰를 수행하지 않았다는 뜻이며 코드의 무결함을 의미하지 않는다.
- 빌드, 테스트, 런타임 및 네트워크 검증은 실행하지 않았다.
- Git 전략의 실제 적용 상태는 확인하지 않았다.

## 설계 질문과 사용자 답변

- 아직 검토 대상이 없어 설계 질문과 사용자 답변 없음.

## 남은 일

- PR, diff 또는 변경 파일과 검토 기준을 받는다.
- 변경 목적·요구사항 및 기존 검증 결과를 확인하고 첫 리뷰를 수행한다.
- 의미 있는 검토 단위마다 지정된 로그 경로에 중간 기록과 최종 결과를 남긴다.
