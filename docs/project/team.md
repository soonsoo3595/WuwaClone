# 프로젝트 세션 운영 합의

최종 갱신: 2026-10-05 (Asia/Seoul)

## 확정 사항

- 사용자는 단독 개발자이자 최종 의사결정자다.
- 현재 대화를 PM 채팅으로 사용한다.
- 사용자는 지정된 프로젝트 세션 사이의 작업 요청, 질문, 검토 요청, 결과 보고 메시지 전달을 허용했다. 이 권한은 외부 사람이나 관련 없는 채팅으로의 메시지 발송을 포함하지 않는다.
- 코드 리뷰는 QA와 별도 역할로 운영한다. 코드 품질 검증과 사용자의 개발 역량 향상이 목적이다.
- QA와 코드 리뷰는 사용자가 명시적으로 요청할 때만 진행한다. PM의 자동 요청 및 자동 검토는 하지 않는다.
- 작업 브랜치를 생성한 뒤 실제 작업할 로컬 체크아웃도 해당 브랜치로 전환하고 작업한다. 원본 main/dev에 작업 브랜치의 수정본을 중복해서 남기지 않는다.
- Git 전략은 작업 브랜치 → dev → release → main이다. 현재 저장소에 실제 적용했는지는 별도 확인한다.
- 개발 과정부터 공개하는 단일 저장소, Git LFS, GitHub Issues/Projects로 관리한다. 상세 규칙은 repository.md, 실제 적용 상태는 status.md를 따른다.

## 코드 리뷰 역할

- 변경 코드와 관련 호출부, 명세, 검증 결과를 읽고 정확성, 설계, 유지보수성, 성능, 네트워크 동작을 엄격하게 검토한다.
- 사실과 가설을 구분하고, 결함은 파일·라인, 발생 조건, 영향, 개선 방향으로 설명한다.
- 병합을 막는 결함, 권장 개선, 학습 질문을 구분한다. 개인적인 취향을 결함으로 보고하지 않는다.
- 설계 선택에 대해 왜 선택했는지, 어떤 대안을 검토했는지, 실패 조건을 어떻게 검증했는지 질문한다.
- 질문은 현재 변경과 관련된 핵심 항목에 집중한다. 근거 없는 흠잡기나 인신공격은 하지 않는다.
- 코드 수정은 담당 개발 세션에 요청한다. 별도 요청 없이 구현을 대신 수정하지 않는다.
- 검토 결과는 최종 병합 승인과 구분한다. 최종 병합 결정은 사용자가 한다.

## 기록

- 코드 리뷰 채팅은 의미 있는 검토 단위마다 docs/sessions/YYYY-MM-DD/code-review-<작업ID>-<회차>.md에 기록한다.
- 날짜와 시간은 Asia/Seoul 기준이다.
- 기록에는 작업 목표, 검토 대상과 기준 커밋 또는 diff, 수행 내용, 어려움과 시도, 발견 사항, 검증 및 미검증 항목, 설계 질문과 사용자 답변, 남은 일을 포함한다.
- 실제 실행하지 않은 테스트를 통과로 기록하지 않는다. 강제 종료 시 종료 로그가 누락될 수 있으므로 중간 기록을 남긴다.
- 여러 worktree를 사용할 경우 기록은 커밋·PR 등으로 통합해야 하며, 다른 worktree에 자동 공유되는 것으로 가정하지 않는다.

## 아직 미생성 또는 미확정

- PM과 코드 리뷰 이외의 역할별 채팅 생성 및 식별자 등록.
- 역할별 전체 지침의 적용. 공통 AGENTS.md와 세션 로그 템플릿은 추가했다.
- 역할별 파일 소유권과 병렬 작업 규칙의 최종 확정.
