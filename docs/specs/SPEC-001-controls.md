# SPEC-001 — 첫 마일스톤 캐릭터 조작 명세

- 상태: 주요 사용자 동작 확정 / 기술 기본안 정리 완료 / 실행 검증 및 사용자 최종 PR 병합 미완료
- 갱신일: 2026-10-04 (Asia/Seoul)
- 관련 Issue: https://github.com/soonsoo3595/WuwaClone/issues/1
- 현재 대상: PC 키보드·마우스, 기본 캐릭터
- 범위: 걷기·달리기·점프·대시·스태미나·3인칭 카메라·사용자 키 변경, 이후 데디케이티드 서버 이동 동기화 검증
- 제외: 공격·전투·수집·로그인 구현

이 문서는 사용자의 설명과 후속 확인을 정리한 명세다. 참고 게임의 실제 내부 구현을 검증한 자료는 아니다. 아래 확정 동작은 구현 완료를 뜻하지 않는다. 기술 설계·QA는 미정 정책과 검증 가능성을 읽기 검토하고, 필요한 최소 선택지만 기획·PM에 전달한다.

## 1. 사용자 확정 동작

| 항목 | 확정 동작 |
| --- | --- |
| 기본 입력 | WASD 이동, Ctrl 걷기·달리기 토글, Space 일반 점프, Shift 대시. 키는 기본 배치이며 사용자가 언제든 변경할 수 있다. |
| 시작 모드 | 게임 시작 시 달리기 모드다. 걷기·달리기는 스태미나를 소모하지 않는다. |
| 이동·회전 | 카메라가 보는 방향을 기준으로 이동하며 캐릭터는 이동 방향을 바라본다. 제자리에서 카메라만 회전하면 캐릭터 방향은 유지한다. |
| 지상 대시 | 이동 입력이 있으면 캐릭터가 바라보는 앞으로 대시한다. 대각선 이동도 해당 방향으로 대시한다. 입력이 없으면 캐릭터 뒤로 대시한다. |
| 지상 이중 대시 | 지상에서 두 번 연속 가능하다. 첫 대시 중 두 번째로 눌러도 첫 대시가 끝난 후 두 번째가 실행된다. 두 번 사용한 뒤에는 잠시 기다려야 다시 사용할 수 있다. |
| 일반 점프 | 지상에서 한 번 점프하며 누르는 시간과 무관한 고정 높이다. |
| 공중 대시 | 지상과 같은 방향 규칙으로 한 번 더 점프하는 동작이다. 이동하며 점프하면 앞으로, 이동 입력 없이 점프하면 뒤로 동작한다. 착지 전 한 번만 사용하며 착지하면 다시 사용할 수 있다. |
| 스태미나 소모 | 대시가 스태미나를 소모한다. 양수 잔량이 소모량보다 적어도 남은 양을 전부 사용해 대시할 수 있다. 이미 0이면 대시할 수 없다. |
| 스태미나 회복 | 소모하지 않는 동안 계속 회복한다. 0까지 소모하면 일정 시간 기다린 뒤 회복한다. 모든 대시 후 회복 지연으로 확대하지 않는다. |
| 카메라 회전 | PC에서는 마우스 수동 입력으로만 회전한다. 이동해도 자동으로 뒤에 정렬하지 않고 사용자가 돌린 방향을 유지한다. |
| 줌 | 플레이 중 마우스 휠로 줌인·줌아웃한다. 어느 줌 거리에서도 마우스로 회전할 수 있다. 별도 게임 설정의 줌 항목은 포함하지 않는다. |
| 카메라 가림 | 구조물에 가리면 카메라가 캐릭터 쪽으로 당겨진다. |
| 캐릭터 투명화 | 카메라가 매우 가까워지면 캐릭터가 투명해지고, 아래에서 캐릭터를 보는 시점에서는 반투명해진다. |

## 2. 개발 중 조정할 수치

사용자는 줌 거리 수치를 개발 중 정하기로 했다. 다른 수치는 현재 값이 없으며 개발·기술 검토에서 초기값과 조정 범위를 제안한다. 수치 미정과 동작 미정을 구분하고, 검증 시 사용한 값을 기록한다.

| 대상 | 조정할 수치 |
| --- | --- |
| 지상 이동 | 걷기·달리기 속도, 가속·감속, 회전 속도 |
| 점프·대시 | 점프 높이, 대시 거리·시간, 공중 대시 수평 이동량·상승량, 지상 이중 대시 후 재사용 대기 시간 |
| 스태미나 | 최대치, 대시 소모량, 회복 속도, 0 소진 후 회복 대기 시간 |
| 카메라 | 기본·최소·최대 거리, 줌 변화량, 감도, 상하 각도 한계, 가림 대응 변화 속도 |
| 투명화 | 근접 거리 경계, 아래 시점 각도 경계, 투명도와 전환 속도 |
| 서버 QA | 적용 지연·손실, 위치·회전 오차 및 수렴 시간 합격 기준. QA·기술 검토 후 검증 전에 정한다. |

## 3. 후속 단계

| 대상 | 현재 처리 |
| --- | --- |
| 게임패드 | 지원 계획은 유지한다. 사용자가 정확한 조작 방식은 나중에 정하기로 했으므로 스틱·버튼 배치를 확정하지 않는다. 검증 착수 시점은 조작 방식 확정 후 PM과 조율한다. |
| Android 터치 | 검증은 후속 단계다. 현재 PC 완료 판정의 필수 조건으로 두지 않는다. |
| 활공·벽 타기·수영 | 사용자가 검증을 후속으로 미뤘다. 현재 완료 판정에 요구하지 않으며 구현 착수·완료로 해석하지 않는다. 스태미나 0 시 활공 낙하·수영 중 가까운 땅 이동 설명은 이 기능의 후속 참고로 보존한다. |
| 캐릭터별 공중 특수 동작 | 공중에 떠서 이동하는 등의 변형은 참고로 남긴다. 이번 기본 캐릭터 동작과 구분한다. |
| 공격 회피 판정 | 사용자는 참고 게임의 대시 회피를 설명했다. 무적·피격 판정은 공격·전투 단계와 함께 검토하며 현재 이동 검증에서 구현 완료를 요구하지 않는다. |

## 4. 최소 정책 결정과 연결 경계 검토

사용자는 다섯 묶음 추천안에 동의하고 지상 이중 대시의 범위·연결·재사용 대기를 추가 확인했다. 아래 정책은 그 결정을 반영한다. 입력 예약 등 내부 경계 처리와 개발 조정 수치는 사용자 동작 결정과 구분한다.

| 묶음 | 확인된 정책 |
| --- | --- |
| 대시·공중 방향 | 이동 입력이 있으면 대시를 누른 순간 카메라 기준 이동 입력 방향을 사용하고, 무입력은 현재 캐릭터 뒤 방향을 사용한다. 일반 점프 중 방향 조절 허용, 대시 진행 중 방향 고정. 하강 중 공중 대시도 다시 위로 도약한다. |
| 입력·종료 | 누름당 1회, 유지 자동반복 없음. 대시 중 점프 입력은 무시하며 예약하지 않는다. 지상 첫 대시 중 두 번째 대시 입력은 받아 첫 동작 종료 후 이어 실행한다. 두 번 사용 후에는 재사용 대기가 필요하다. 시간 만료·진행을 막는 충돌·공중 대시 중 착지로 종료하고 소모 환불 없음. 턱에서 떨어져도 공중 대시 가능하며 실제 지면 착지에서만 공중 횟수 초기화한다. |
| 스태미나 | 대시 시작 순간 한 번 소모. 양수 잔량이면 대시 중에도 회복한다. 0이면 소진 순간부터 지연 후 회복. 거부 입력은 회복 대기를 연장하지 않고 회복으로 양수가 되면 대시 가능하다. |
| 키 변경 | PC 이동 4방향·걷기/달리기 토글·점프·대시를 단일 키로 재배치. 마우스 회전·휠은 고정, 조합키·게임패드·터치는 후속. 중복 키는 안내 후 거부. 즉시 적용·로컬 저장·재시작 유지·기본값 복원. |
| 카메라·투명화 | 가림 중 휠로 희망 거리를 바꾸고 해소 시 최신 희망 거리로 복원. 실제 카메라 위치로 투명화 판단, 근접 완전투명 우선. 조건 해제 시 남은 조건 재평가, 모두 해제 시 원래 외형 복원. 자신의 화면의 조작 캐릭터 메시만 영향받는다. |

### 지상 이중 대시 — 확정 동작과 기술 검토 항목

사용자는 짧게 두 번 눌러도 두 번 대시하며 두 번째 동작은 첫 대시가 끝난 뒤 실행한다고 확인했다. 두 번 연속 사용은 지상에 적용하고 공중은 착지 전 한 번이다. 두 번 사용한 뒤에는 잠시 기다려야 다시 사용할 수 있다. 대기 시간은 개발 조정값이다. 각 대시의 스태미나 조건은 유지한다. 이전 추천의 대시 재입력 무시 및 지상 별도 쿨다운 없음은 이 결정으로 대체한다.

두 번째 입력 예약의 유효기간, 한 번만 사용한 경우 연속 사용 상태 해제, 충돌·낙하 등에서 예약 유지 여부, 대기 시작·종료와 방향·스태미나 판정 시점의 경계 처리는 기술 설계·QA가 최소안을 제안할 항목이다. 사용자에게 확정받은 지상 두 번·순차 실행·사용 후 대기와 공중 한 번을 변경하지 않는다. 기술안을 사용자 확정으로 기록하지 않는다.

### 기술 기본안 — 구현·검증 중 조정 가능, 사용자 직접 확정과 구분

기술 설계·QA 추가 읽기 검토와 PM 조율을 반영한 기본안이다. 사용자 직접 확정이나 실행 검증이 아니며 구현·검증 중 평가해 조정할 수 있다. 구체 엔진 처리 순서는 구현 설계에서 기록한다.

| 대상 | 기술 기본안 |
| --- | --- |
| 예약 | 첫 지상 대시 진행 중 새 누름 하나만 예약한다. 정상 시간 만료까지 유지하고 종료 직후 한 번 실행을 시도한다. 유지 입력·세 번째 누름은 추가 예약·덮어쓰기·연장을 하지 않는다. 짧은 두 번 누름을 버리는 별도 예약 만료값은 두지 않는다. |
| 첫 대시만 사용 | 정상 종료 후 연결 입력 허용 시간 안의 새 누름은 두 번째로 처리한다. 추가 실행 없이 만료되면 연결 상태를 해제하며 단일 사용에 이중 사용 후 대기를 부과하지 않는다. 입력 시각이 만료보다 이르면 두 번째, 같거나 이후면 새 첫 번째다. 연결 시간은 개발 조정값이다. |
| 방향·소모 | 예약을 만든 누름 순간 방향을 저장하고 실행 시 다시 읽지 않는다. 예약 때 선소모하지 않으며 실제 시작 순간 회복을 정산한 잔량으로 판정한다. 양수이면 한 번 소모·횟수 반영, 0이면 예약 폐기. 이후 회복으로 자동 재생하지 않는다. 거부된 두 번째는 이중 사용 후 대기를 새로 만들지 않는다. |
| 취소·상태 종료 | 첫 지상 대시 중 공중 이탈하면 지상 동작 종료·예약 취소·첫 연결 상태 종료. 진행을 막는 충돌 종료는 예약을 취소하되 첫 사용은 연결 시간 동안 유지한다. 취소 입력을 공중 동작이나 착지 후 동작으로 변환하지 않는다. 승인된 실행 비용은 환불하지 않으며 공중 동작에는 새 누름이 필요하다. |
| 재사용 대기 | 두 번째 실제 시작 승인으로 두 번 사용을 계산하고 두 번째 실제 종료부터 대기를 시작한다. 세 번째 입력 및 대기 중 입력은 버리고 예약·연장·자동 실행하지 않는다. 공중 이탈·착지는 이미 발생한 지상 대기를 지우지 않는다. 대기 만료 후 새 누름부터 허용하며 스태미나 조건은 별도로 충족해야 한다. |
| 공중 사용권 | 공중 착지 전 1회 사용권은 지상 재사용 대기와 별개다. 실제 착지는 공중 사용 횟수만 초기화하며 이미 생긴 지상 재사용 대기를 초기화하지 않는다. |
| 재처리 | 서버 최종 권한 및 소유 클라이언트 예측을 기술 기본안으로 둔다. 예약·방향·연속 횟수·만료·대기·스태미나를 함께 복원·보정하며 같은 누름의 재전송·재처리로 중복 예약·소모를 만들지 않는다. UE API는 아직 확정하지 않는다. |

첫 사용 후 공중 이탈 시 연결 상태를 유지하는 QA 제안과 종료하는 기술 설계 제안의 차이는 PM이 기술 설계 최소안을 채택해 조율했다. 첫 대시→이탈→재착지→새 지상 입력은 연결 상태가 종료됐으므로 새 첫 대시로 해석한다. 이 기술 경계는 사용자 직접 확정이 아니며 재착지 반복의 지상 대기 우회 여부를 검증해 구현 평가 때 조정할 수 있다.

QA는 연결 시간을 재사용 대기와 같은 초기값으로 시작한 뒤 필요하면 분리하는 안을 제안했다. 이는 합의된 수치나 사용자 확정이 아닌 튜닝 제안이다.

스프링암, 지정 상승 속도, 경계 처리 순서, 서버 권한·예측, 재처리 중복 소모 방지, 스태미나 소유자 공유, 키 변경 시 이전 입력 해제와 UI 입력 분리는 기술·QA 항목이다. 조정 수치는 QA 전에 사용값을 기록한다. PM이 전달한 구현 가능 의견은 실행 검증 결과가 아니다.

## 로컬 동작 완료 조건

아래는 관찰할 확인 항목이며 통과 기록이 아니다. 최소 정책과 검증 수치가 정해지면 같은 절차로 재현할 수 있게 구체화한다.

| 대상 | 관찰 가능한 확인 항목 |
| --- | --- |
| 이동 | 시작 시 달리기, Ctrl 토글, 입력 시작·유지·해제와 정지. 전후좌우·대각선 및 카메라 방향 변경에서 이동·캐릭터 회전 규칙 확인. 대각선 속도의 의도하지 않은 증가 확인. |
| 점프·대시 | 지상 1회 고정 높이 점프. 이동 입력 유무와 대각선의 지상·공중 대시 방향 확인. 착지 전 공중 대시 2번째 입력 거부와 착지 후 재사용 확인. 입력 반복·충돌 등은 확정 정책 적용. |
| 지상 이중 대시 | 짧은 두 번 누름과 첫 대시 후 추가 누름에서 두 동작이 순차 실행되는지 확인한다. 두 번 사용 후 대기 중 추가 입력 거부 및 대기 종료 후 재사용을 확인한다. 예약·충돌 등은 기술 경계 정책 적용. |
| 이중 대시 경계 QA 계획 | 첫 시작 직후·종료 직전 누름, 유지·세 번 이상 연타, 연결 만료 직전·정확한 경계·직후, 예약 후 방향 변경, 예약 당시와 실행 당시 잔량 변경, 충돌·낙하·재착지와 대기 경계를 반복한다. 승인 횟수·방향·예약 생성/취소/소비·소모·대기 시각을 기록한다. 미실행 계획이다. |
| 공중 이탈·재착지 QA 계획 | 첫 대시→이탈→재착지→새 지상 누름이 새 첫 대시인지 확인하고, 반복 재착지로 지상 대기를 우회하는지 평가한다. 이미 두 번 사용한 뒤 이탈·재착지해도 지상 대기가 유지되는지, 대기 중 공중 1회 사용권은 별도인지 확인한다. 기술 기본안 평가이며 미실행이다. |
| 스태미나 | 충분한 잔량, 소모량 미만 양수 잔량, 0에서 각각 대시 결과 확인. 양수 부족 잔량은 대시 실행 후 0, 이미 0이면 대시 이동 없음. 비소모 중 회복과 0 소진 후 대기·회복 재개 확인. |
| 키 변경 | 새 배치로 기능 조작 확인. 확정한 저장·중복 처리·지원 범위·복원 규칙을 각각 확인. |
| 카메라 | 마우스 회전 및 방향 유지, 자동 정렬 없음, 휠 줌과 모든 줌 거리에서 회전 확인. 구조물 접근·이탈 시 당김·복원 확인. |
| 투명화 | 근접 및 아래 시점 조건의 적용·해제, 겹침 처리와 원래 외형 복원 확인. |

## 서버 이동 동기화 완료 조건

로컬 동작 검증 이후 별도 단계로 확인한다. 기술 설계와 QA의 읽기 검토는 실행 증거를 대신하지 않는다.

- 데디케이티드 서버에 클라이언트 2개 이상이 연결된 환경에서 자신의 입력 반응과 다른 클라이언트가 보는 이동을 구분해 관찰한다.
- 걷기·달리기 전환, 방향 변경, 점프·착지, 지상·공중 대시, 장애물 충돌의 위치·회전·이동 상태를 서버와 각 클라이언트에서 비교할 증거를 남긴다.
- 서버와 조작 클라이언트에서 공중 대시 1회 제한·착지 초기화, 양수 잔량 대시·0 상태 거부·회복 지연을 비교한다. 다른 클라이언트에는 대시 이동 결과를 확인하고 스태미나 수치 공개 범위는 기술 검토에서 정한다.
- 지상 이중 대시의 순차 실행, 대시별 스태미나 소모, 두 번 후 재사용 대기를 서버와 조작 클라이언트에서 비교하고 다른 클라이언트의 두 동작 관찰 증거를 남긴다.
- 이중 대시 경계 사례를 정상망·지연·손실·복합 조건에서 반복한다. 입력 식별자와 예약 생성/취소/소비, 시작/종료·방향·횟수·잔량·대기 시각을 서버와 조작측에서 대응시킨다. 재처리 중 중복 소모·세 번째 실행·취소 예약 부활이 없고 서버 거부 후 상태·위치가 합의한 기준 안에 수렴하는지 확인한다. 현재는 미실행 QA 계획이다.
- 제자리 카메라 회전 시 다른 클라이언트가 보는 캐릭터 방향 유지 여부를 확인한다. 카메라 화면 자체의 공유는 요구하지 않는다.
- 투명화가 각 클라이언트 화면에 미치는 범위는 최소 정책 확정 후 확인한다.
- 지연·손실 조건에서 보정, 이동 상태 불일치, 착지 후 위치 차이와 수렴을 기록한다. QA·기술 검토에서 정한 오차·시간 기준으로 판정한다.
- 실행 환경, 기준 커밋, 사용 수치, 클라이언트 수, 네트워크 조건, 반복 절차, 결과 로그 또는 영상을 기록한다. 연결 성공만으로 이동 동기화 완료를 판정하지 않는다.

## 현재 완료 상태와 다음 단계

- 완료: 사용자와 주요 PC 조작 동작·대시·스태미나·카메라 기능을 확정하고 후속 범위를 분리했다. 확정 동작, 조정 수치, 후속 단계, 최소 정책을 정리했다.
- 미정: 개발 조정 수치. 연결 경계는 PM 조율 기술 기본안으로 기록했으며 구현·검증 중 조정 가능하다. 지상 두 번·순차 실행·두 번 후 대기와 공중 한 번은 사용자 확인됐다. 게임패드 세부 조작과 후속 기능은 이번 결정을 기다리는 항목으로 되돌리지 않는다.
- 검토 정리 완료: 다섯 묶음 정책과 지상 이중 대시 사용자 결정을 반영했다. 기존 재입력 무시·지상 쿨다운 없음은 대체됐다. 기술 설계·QA 검토 및 PM 조율 기술 기본안을 정리했고 구현 가능 의견과 실행 검증을 구분한다.
- 구현·검증 상태: 이 기획 작업에서는 코드·에셋 구현, UE 빌드, 로컬 실행, 서버 네트워크 QA를 수행하지 않았다.
- 통합 상태: 문서 PR 준비를 Git 담당에 요청한다. 문서 커밋·PR·dev 통합은 아직 완료되지 않았으며 병합 승인도 없다. Issue #1 완료는 문서 PR의 사용자 최종 병합 결정 후 dev 통합을 기준으로 한다.
